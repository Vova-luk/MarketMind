# Миграции общей базы MarketMind

SQL-файлы этой папки встраиваются в Go-бинарник через `embed` и применяются
пакетом `utils/migrator` с помощью Goose. API уже вызывает мигратор после
подключения к PostgreSQL и до запуска HTTP-сервера. При ошибке миграций API
не запускается. Tracking использует ту же схему `market_mind`.

Для запуска API с миграциями из `backend`:

```bash
cd services
go run ./api/cmd -config api/config/config.yaml -env-file ../.env
```

PostgreSQL должен быть доступен; настройки подключения берутся из конфига API.
Повторный запуск применяет только ещё не выполненные версии. История хранится
в таблице `public.goose_db_version`; параллельное применение защищено
PostgreSQL session lock.

## Схема

Миграции создают шесть таблиц: `cryptocurrencies`, `exchanges`, `markets`, `users`,
`subscriptions`, `alerts`. В `exchanges.id` используется `INTEGER` без
автогенерации: идентификаторы бирж задаются явно при добавлении справочника.

Цены и значения алертов хранятся в `NUMERIC`, чтобы поддерживать дробные
значения без потери точности. Telegram ID пользователя, пара пользователь–рынок
и пара криптовалюта–биржа защищены от дублирования. Внешние ключи сохраняют
заданный `ON DELETE CASCADE`; для запросов и удаления добавлены индексы.

## Добавление миграции

Одна версия — один файл, например `007_add_alert_state.sql`:

```sql
-- +goose Up
-- Изменение схемы.

-- +goose Down
-- Обратное изменение.
```

Уже применённые версии не редактируются: изменения добавляются следующим файлом.
Goose использует транзакции по умолчанию. Полный откат удаляет таблицы в обратном
порядке, а затем схему `market_mind`, без `CASCADE` при удалении схемы.

## Проверка и ручной откат

Для ручного управления можно установить CLI той же версии, что в `go.mod`:

```bash
go install github.com/pressly/goose/v3/cmd/goose@v3.29.0
```

Из `backend/services`, указав строку подключения в `GOOSE_DBSTRING`:

```bash
export GOOSE_DRIVER=postgres
export GOOSE_MIGRATION_DIR=utils/migrations
goose status
goose up
goose down
```

`down` откатывает одну последнюю миграцию. Откат удаляющих таблицы версий
удаляет и их данные; полный цикл проверки выполняется на отдельной тестовой БД.

## Автоматические тесты

```bash
go test ./utils/migrator
```

Без `MIGRATOR_TEST_DSN` выполняются проверки упаковки миграций, уникальности
версий и обработки ошибок. Для полного PostgreSQL-теста задаётся
`MIGRATOR_TEST_DSN` — строка подключения с правом создавать базы:

```bash
go test -race -count=1 -run TestMigrationLifecycle -v ./utils/migrator
```

Тест создаёт собственную БД `marketmind_migrations_*` и удаляет только её.
Он проверяет первый и повторный `Up`, ограничения и точность чисел, одиночный
`Down`, полный откат, повторное применение и атомарный откат ошибочной миграции.
В CI PostgreSQL запускается отдельным сервисом, поэтому этот тест не пропускается.
