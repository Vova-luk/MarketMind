# MarketMind


## Процесс разработки

Разработка MarketMind ведётся по упрощённой модели Git Flow.

### Ветки

- `main` — стабильная версия приложения.
- `develop` — основная ветка разработки.
- `feature/<task-id>-<name>` — разработка новой функциональности.
- `fix/<task-id>-<name>` — исправление ошибок.

`task-id` — идентификатор задачи в Taiga.

Все рабочие ветки создаются от актуальной `develop`.

### Работа с Git

1. Получить актуальную версию `develop`.
2. Создать отдельную ветку для задачи.
3. Реализовать изменения и создать коммиты.
4. Отправить ветку в GitHub.
5. Создать Pull Request в `develop`.
6. Дождаться прохождения CI и ревью.
7. После одобрения выполнить merge.

Прямые изменения в `main` и `develop`
не допускаются.

Стабильные изменения переносятся из
`develop` в `main` через Pull Request.

### Соглашение о коммитах

Используется формат Conventional Commits:

`<type>: <description>`

Основные типы:

- `feat` — новая функциональность.
- `fix` — исправление ошибки.
- `docs` — изменение документации.
- `refactor` — переработка кода без изменения поведения.
- `test` — добавление или изменение тестов.
- `ci` — настройка CI/CD.
- `chore` — вспомогательные изменения.

Примеры:

- `feat: add price tracking`
- `fix: handle exchange API timeout`
- `docs: update development workflow`
- `ci: configure Go tests`

Один коммит должен содержать одно логически
завершённое изменение.

### Continuous Integration (CI)

Для автоматической проверки изменений
используется GitHub Actions.

CI запускается при создании и обновлении
Pull Request в `develop` и `main`,
а также при push в эти ветки.

Проверки Go:

- `go test ./...` — запуск тестов.
- `go vet ./...` — статический анализ.
- `go build ./...` — проверка сборки.

Слияние Pull Request разрешается после
успешного прохождения обязательных проверок
и одобрения изменений другим разработчиком.

### Code Review

Каждый Pull Request должен пройти ревью
как минимум одного участника команды.

При наличии замечаний автор исправляет
код в той же рабочей ветке.

После успешного слияния рабочая ветка
может быть удалена.
